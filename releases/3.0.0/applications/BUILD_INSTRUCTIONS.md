# LUMAFLOW Developer Guide

## Build
```
sudo apt install ninja-build qt6-base-dev qt6-base-dev-tools libqt6opengl6-dev libgl-dev \
     libavformat-dev libavcodec-dev libswscale-dev libavutil-dev zlib1g-dev libsqlite3-dev libasound2-dev
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
xvfb-run ctest --test-dir build --output-on-failure      # GPU tests need an OpenGL 3.3 context
cd build && cpack -G "DEB;TGZ"
```
Options: `LUMAFLOW_BUILD_GUI`, `LUMAFLOW_BUILD_TESTS`, `LUMAFLOW_WITH_FFMPEG`, `LUMAFLOW_WITH_ALSA`.

## Architecture
| Library / dir | Contents |
|---|---|
| `lumacore` | `core/` (log, parameter registry), `protocols/` (Art-Net, sACN, OSC, MIDI, timecode, NetworkIO thread), `fixtures/` (model, capabilities, GDTF, MVR, colour engine), `pixelmapping/`, `spatial/`, `console/` (personality generator, mapping engine), `timeline/`, `storage/` (project I/O, zip), `audio/`, `media/` (FFmpeg player, SQLite library), `effects/`, `nodes/` (graph + GLSL compiler), `layers/`, `remote/`, `sync/`, `plugins/`, `ai/`, `recovery/` |
| `lumarender` | `renderer/` (offscreen OpenGL renderer, render thread, adaptive quality), `output/` (output regions, FFmpeg recorder) |
| `lumaengine` | `app/Engine*.cpp` – owns and connects all subsystems |
| `lumaflow` | `ui/` Qt Widgets application |
| `lumaflow-cli` | headless tools (render, benchmark, export, import, validate, probe) |

### Threads
Main (UI + 60 Hz control tick: timeline, cue follow, MIDI poll, autosave) · `lf-render` (GPU, pixel mapping, spatial DMX, recording) ·
`lf-network` (all UDP sockets, rate-limited DMX transmit) · `lf-remote` (HTTP) · `lf-sync` · decoder threads per video · audio input thread ·
watchdog thread. The renderer receives immutable `RenderInput` snapshots; no network, disk or UI operation runs on the render thread.

### Parameter registry
Every controllable value has a stable id (`master.intensity`, `layerN.speed`, ...). Console DMX, OSC, MIDI, remote, timeline, sync and
UI all write through `MappingEngine::write()` (ownership policies) into the registry; listeners fan out feedback.

### Effects
An effect is a GLSL body `vec4 effect(vec2 p, vec2 uv, float t)` compiled between `resources/shaders/prelude.glsl` and `main.glsl`.
Built-in effects are generated by `tools/gen_effects.py`. Programs are cached per effect id + source hash; a failing compile keeps the
previous program and reports a fault.

### Personality catalogue
`PersonalityGenerator::catalogue()` is an **append-only** list. Never reorder or remove entries: lower modes are prefixes of higher
modes and console patches depend on channel positions. `ProfileManager` requires operator approval for any change and flags breaking ones.

## Plugin SDK
Header: `sdk/include/lumaflow_plugin.h` (C ABI, `LF_PLUGIN_API_VERSION 1`). Example: `sdk/examples/effect_starfield/starfield.c`.
Export `lf_plugin_query()` returning `LfPluginInfo`; optional `lf_plugin_init(const LfHostApi*)` and `lf_plugin_shutdown()`.
Categories: effects, shader nodes, protocols, fixture importers/exporters, output modules (frame sink callbacks), media decoders, automation.
Install into `<data dir>/plugins` or `<prefix>/lib/lumaflow/plugins`. Each library is first loaded by `lumaflow-cli plugin-probe`
in a separate process; a crash there marks the plugin as failed without affecting the show.

## Tests
`tests/test_*.cpp` (Qt Test): protocols, fixtures/GDTF/MVR/colour, pixel mapping/spatial, console personality/mapping,
timeline/storage/nodes/audio/AI, GPU engine (needs GL), network integration over loopback, plugins (incl. crash isolation).

## File formats
JSON with `format` and `schemaVersion`. Projects: `ProjectIO::migrate()` upgrades v1 → v2 → v3; files from newer versions are refused.


## Installers not included
Windows (NSIS/ZIP), macOS (DMG) and the AppImage are produced by `.github/workflows/build.yml`; they were not built in the release environment (progress/BLOCKERS.md B3/B4).
